# 组合注意事项证据契约

## 目标

让 `COMBINED_WITH` 只表达原文明确写出的共同服用条件。组合头是 `COMBINATION`，成员来自头键；尾可以是成分、营养素、药物、药物类别或人群。关系名称在界面和工具输出中统一显示为“组合注意事项”，避免把普通的共同服用提醒夸大为“禁忌”。

## 证据边界

- 成员、尾端和 `effect` 必须都能在同一条 `quote` 中逐字命中；别名只能使用维护过的 `EntityAliases`。
- `quote` 必须逐字存在于文档正文；缺成员、尾端或后果的引文拒绝入库。
- 不从关系名称推断“两两无事、三者才有事”或任何独特三阶风险；原文只写共同服用条件时，按原文表述。
- `effect` 是原文片段，不能由模型归纳或改写。
- 现有 `KB-0053` 作为正例：钙剂、铁剂、锌共同补充时存在吸收竞争，尾端可落到原句明确提到的锌。

## 验收证据

```powershell
# 在已配置 Java 21 的终端执行
mvn -o -pl agent-core,knowledge-service,ai-service -am `
  '-Dtest=GraphRelationTest,TripleValidatorTest,GraphServiceRecallTest,InteractionCheckToolTest,KnowledgeGraphBuilderParseTest' `
  '-Dsurefire.failIfNoSpecifiedTests=false' test
```

验收包括：组合类型签名、KB-0053 正例、成员/尾端/effect 缺证拒绝、别名命中、组合成员完整覆盖查询，以及工具和前端图谱的“组合注意事项”展示。
