# T1 售后工具交易契约

售后工具直接使用交易接口的 `REFUND_ONLY`、`RETURN_REFUND`、`EXCHANGE`，仅容忍大小写和首尾空白。不保留工具私有的 `REFUND`、`RETURN` 别名，以免确认载荷与实际交易类型存在两种解释。

`orderItemId` 是正整数订单行标识，`reason` 与交易请求一致，为必填非空文本（最多 64 字）。用户确认后执行工具时，工具通过已有 `GET /after-sales/preview` 读取同一订单行、类型与质量问题参数的资格；不符合时保留服务端原因，不执行 `POST /after-sales`。预检失败不假定允许，提交时仍由交易服务重新判断政策与并发在途售后。

预检是已有 API 与售后确定性流程的一部分，不宣称存在 `after_sale_preview` 工具。回执 `statusText` 由交易响应直接提供，金额单位保持为分。

验收：Java 21 执行 `mvn -o -pl ai-service -am -Dtest=AfterSaleToolContractTest,WriteToolConfirmationTest,AfterSaleFlowTest -Dsurefire.failIfNoSpecifiedTests=false test`。核对三种类型原样透传、旧别名拒绝、预检拒绝不写入、服务异常不重发写请求、状态与退款字段 JSON 映射。

回滚仅还原售后工具、接口注释、回执注释及对应测试；不改交易存量数据、数据库或配置。不调用真实售后提交接口。
