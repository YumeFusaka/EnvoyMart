# RAG 知识检索模块设计

## 整体流程

```
用户 query
    │
    ├──→ BM25 关键词检索（CJK bigram 分词）──→ 排序 ──┐
    │                                                ├──→ RRF 融合 → 候选集
    └──→ 向量检索（EmbeddingModel + Milvus/内存）──→ 排序 ──┘        │
                                                                     ▼
                                              cross-encoder 重排（gte-rerank）
                                                                     │
                                                              Top-K → Prompt 注入
```

**为什么是这个顺序**：召回追求"不漏"（多路 + 多留候选），重排追求"排得准"（逐对打分），两者职责不同。

## 一、召回

### BM25 关键词检索

标准 BM25，`k1 = 1.5`、`b = 0.75`。

- **分词**：`TextTokenizer` 对 CJK 按字符二元组（bigram）切分，与 Lucene `CJKAnalyzer` 同策略，无需词典即可让中文查询命中；拉丁字母/数字按非字母数字边界切分
- **文档长度**按词元数计，中文与英文共用同一套归一化
- **索引文本** = 标题 + 正文 + 标签，让标题和标签也参与匹配

> 曾经的坑：按空白符分词时，中文整句会被当成一个词元，任何中文查询都召回为空。这是本模块最初最严重的问题。

### 向量检索

- 入参是**原始文本**，向量化由 `VectorStore` 实现自己负责
- 生产：`MilvusVectorStore` → Spring AI `MilvusVectorStore` + `EmbeddingModel`
- 本地：`InMemoryVectorStore` → 手写 IVF 索引（k-means 聚类，检索时只探最近的簇，结果不足则回退暴力搜索）

> 为什么把向量化下沉到存储层：上层用 A 模型编码、存储用 B 模型编码会导致向量空间错配，这类 bug 很难查。

## 二、融合：RRF

```
score(d) = Σ 1 / (k + rank(d))，k = 60
```

两路结果**按 docId 对齐**——向量路返回的是切片、关键词路返回的是文档，只有归一到文档粒度，同一篇文档的排名才能相加。

> 曾经的坑：用 chunkId 对齐时两路 key 不同，RRF 实际只是并集，融合完全没生效。

## 三、重排

召回后保留 `topK × 3` 个候选，交给 `Reranker` 精排：

- `DashScopeReranker`：调用百炼 `gte-rerank-v2`（cross-encoder），让 query 与候选逐对打分
- 任何异常（超时、非 2xx、解析失败）都降级为 `Reranker.NOOP`，保持原顺序，不让检索整体失败

## 四、评测

`RetrievalEvaluator` 用标注样本算三个指标：

| 指标 | 含义 | 回答的问题 |
|------|------|-----------|
| Hit Rate@K | Top-K 里是否至少命中一篇相关文档 | 召回有没有 |
| MRR | 第一篇相关文档的排名倒数 | 排序好不好 |
| NDCG@K | 带折损的整体排序质量 | 排得好到什么程度 |

`RetrievalQualityTest` 用两组样本对比（BM25 路，向量库留空）：

| 样本组 | 条数 | Hit Rate@3 | MRR |
|--------|------|-----------|-----|
| 字面重合查询 | 8 | 1.000 | 1.000 |
| 口语化改写 | 4 | 0.750 | 0.750 |

口语化那组掉分，正是引入向量检索与重排的量化依据——而不是"感觉向量检索更先进"。

## 五、降级策略

| 故障场景 | 降级行为 |
|---------|---------|
| 无 Embedding 模型 | 回退本地 Ollama（nomic-embed-text），再不可用则用哈希向量 |
| 无 Milvus | 回退内存 IVF 向量库 |
| 重排服务不可用 | 保持召回顺序 |
| 文档集合为空 | 跳过 RAG 注入，仅使用模型自身知识 |
